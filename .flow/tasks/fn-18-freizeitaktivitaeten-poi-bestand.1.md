## Approach
- ACHTUNG: Tabellenname `poi_activities` — `activities` ist die Social-Feed-Tabelle (Namens-Kollision, Epic E1).
- **Verbindliches Spaltenschema `poi_activities`** (Typen/Constraints; Tasks 2-6 bauen darauf):
  - `id uuid pk default gen_random_uuid()`
  - `source text not null` ('deskline'), `source_region text not null` (**insert-only**: Region der Erst-Sichtung; ist im Update-Pfad NIE enthalten, sonst flappt der Wert bei Mirror-Regionen), `source_id text not null`, UNIQUE(source, source_id)
  - `name text not null`, `slug text not null` (UNIQUE via Index-Migration), `shortid text not null` (die 12 Hex-Zeichen als EIGENE Spalte mit UNIQUE-Index — der Resolver-Fallback laeuft darueber, nicht ueber Suffix-Scans auf slug), `description text`, `description_short text`
  - `tags text[] not null default '{}'`, `topics_raw jsonb`, `setting text null check (setting in ('indoor','outdoor','mixed'))` — **deterministisches Wetter-Signal**: wird ausschliesslich aus der Topic-Whitelist abgeleitet (jeder Whitelist-Eintrag deklariert indoor/outdoor/mixed; z.B. Hallenbad=indoor, Mountaincart=outdoor, Museum=indoor); NULL = unbekannt. Task 6 filtert Regen-Queries NUR ueber dieses Feld.
  - `lat double precision not null`, `lng double precision not null`, `town text`, `gemeinde_slug text`, `bundesland text not null` — **kanonische lowercase-ID wie im Bestand** (`burgenland`, `steiermark`, `kaernten`, ...); **autoritative Quelle ist die gematchte Gemeinde-Registry-Zeile** (ALL_GEMEINDEN traegt das Bundesland pro Gemeinde), NICHT die REGIONS-Config — die enthaelt Eintraege mit bundesland='Österreich' und dient nur als Fallback-/Log-Feld
  - `opening_times_raw jsonb` (Deskline-Original) + `opening_times jsonb` (normalisiert nach Epic-E8-Vertrag: Array von {from,to,timeFrom,timeTo,weekdays-Bitmaske Mo=1..So=64|null}; '00:00'/'00:00' = durchgehend; EINZIGER Lesepfad fuer Badge/Gate), `open_status int` (Deskline-Enum, Semantik im Migrations-Kommentar), `online_bookable boolean not null default false`. Normalisierungs-Funktion opening.ts gehoert zu diesem Task inkl. 3 Fixtures (Mountaincart-Saisonfenster, Supermarkt-Wochentags-Bitmaske, Ladestation durchgehend).
  - `images jsonb` (Array mit urls/copyright/license/author), `guest_cards jsonb`, `price_hint text`
  - `affiliate_product jsonb` — **Mindest-Contract (Task 5 baut darauf):** `{product_code, title, teaser, image_url, price_from, currency, rating, review_count, url, matched_at, refreshed_at}`
  - `content_fingerprint text not null`, `duplicate_of uuid null references poi_activities(id)`, `visible boolean not null default true`
  - `last_seen_run_seq bigint` (Provenienz: JEDER full_attempt aktualisiert), `last_seen_complete_run_seq bigint` (**NUR complete_runs aktualisieren; Prune UND Canonical-Liveness laufen AUSSCHLIESSLICH ueber dieses Feld** — sonst haelt ein Fehllauf-Sighting POIs am Leben, die in 2 kompletten Laeufen fehlten), `last_seen_at timestamptz`, `seen_regions text[] not null default '{}'` (all-time-Union, reine Provenienz) — Ordnung IMMER ueber run_seq-Werte (monoton), nie ueber Run-UUIDs
  - `created_at timestamptz not null default now()`, `updated_at timestamptz not null default now()`
- `poi_activity_runs`: `run_id uuid pk`, `run_seq bigint generated always as identity unique` (monotone Ordnung fuer Canonical-Wahl + Prune — UUIDs sind nicht zeitlich ordbar), `started_at`, `finished_at`, `regions_ok jsonb`, `regions_failed jsonb`, `is_complete boolean not null default false`.
- RLS: `poi_activities` public-read NUR fuer `visible=true AND is_closed=false` (RLS-Policy mit WHERE-Klausel — versteckte Duplikate/geprunte/gesperrte Rows sind client-seitig NICHT lesbar); Slug-/Shortid-/Duplicate-Resolution (Task 3) laeuft deshalb server-seitig ueber den Service-Role-Client. `poi_activity_runs` NUR service-role. KEINE GIN/trgm-Indizes in der Basis-Migration.
- Zusaetzliche Spalte `is_closed boolean not null default false` — dauerhaft gesperrte/geschlossene POIs (GESPERRT-Praefix / entsprechender open_status) werden importiert (Datenpflege, Wiedereroeffnungs-Erkennung), aber ueberall ausgeschlossen (Anzeige-Bedingung visible AND NOT is_closed); bewusst SEPARAT von `visible`, das ausschliesslich Prune/Dedup gehoert.
- Index-Migration (separat, nach Initial-Load; jeweils mit Task-Bezug im Kommentar): `create extension if not exists pg_trgm;` · UNIQUE(slug) [Task 3] · UNIQUE(shortid) [Task 3 Resolver-Fallback] · btree(gemeinde_slug) WHERE visible [Task 3/4] · btree(bundesland) WHERE visible [Task 3] · GIN(tags) [Task 3/6] · GIN(name gin_trgm_ops) [Task 6 — trgm NUR auf name, description ist Sekundär-Scoring ohne Index] · btree(lat), btree(lng) [Task 4 bbox-Nearby, Muster Events] · btree(content_fingerprint) [Task 2 Dedup-Gruppen] · btree(last_seen_complete_run_seq) [Task 2 Prune/Liveness] · btree(name, id) WHERE visible [Task 3 Cursor-Pagination-Sortierung].
- taxonomy.ts: kuratierte Deskline-Topic-Whitelist -> bestehende TAGS-Werte (read-only-Import der Typen aus enrichment-taxonomy.ts erlaubt, Datei selbst NICHT aendern — fn-14-Konflikt, Epic E3). Whitelist deckt Action/Freizeit/Familie/Baeder/Kultur ab (Kartsport/Kartbahn, Sommerrodelbahn, Hochseilgarten, Klettersteig, Freibad, Museum, ...); jeder Whitelist-Eintrag traegt verpflichtend `{tags: [...], setting: 'indoor'|'outdoor'|'mixed'}`. **Aggregations-Regel bei mehreren gemappten Topics pro POI (deterministisch):** alle indoor -> 'indoor'; alle outdoor -> 'outdoor'; irgendein Konflikt oder ein 'mixed'-Topic -> 'mixed'; keine gemappten Topics -> NULL. Gastro/Shops/Weingueter/E-Ladestationen -> nicht importieren. Unmapped Topics -> skip + Log-Liste.
- slug.ts: `{slugify(name)}-{shortid}` mit **exakter shortid-Definition: erste 12 Hex-Zeichen von sha1(`${source}:${source_id}`), lowercase** (48 bit — kollisionsfest bei 20k+ Rows; 8 Hex waeren es nicht); Slug wird beim Insert fixiert, nie regeneriert (Epic E5). Task 3 nutzt dieselbe Funktion fuer den Redirect-Resolver.
- gemeinde-match.ts: nearest-Haversine gegen ALL_GEMEINDEN (src/lib/gemeinden/data.ts, haversineKm wiederverwenden) (Epic E4).
- price-hint.ts: deterministischer Euro-Regex mit Anti-Patterns (Jahreszahlen "ab 2018", Hausnummern, kW-Angaben) — kein KI-Enrichment.
- fingerprint.ts: content_fingerprint = Hash aus normalisiertem Namen (lowercase, Mojibake-bereinigt, whitespace-kollabiert) + **exakt spezifizierter Koordinaten-Quantisierung: `round(lat*1000)/1000` und `round(lng*1000)/1000`** (3 Dezimalstellen, Grid ~111 m x ~75 m in AT). Grid-Kanten-Effekte sind bekannt und akzeptiert (Fingerprint ist Fallback-Heuristik, nicht Genauigkeitsgarantie); Tests arbeiten fixture-basiert gegen genau diesen Algorithmus (Epic E11).
