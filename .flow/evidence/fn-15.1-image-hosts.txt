Important behavior notes (Codex-Round-4):
  • `search` field intentionally OMITTED throughout. Next.js Image-Optimizer
    normalizes query-strings away at the proxy layer, so URLs with
    cache-busters like `?v=12345` still match. Explicit `search` would
    only be needed for SOURCE hosts that 404 without a specific query
    parameter; we haven't observed that in the Landing-card scrape pool.
  • Redirect chains (e.g. CDN A → CDN B) are handled automatically because
    Vercel Image Optimization follows the redirect server-side; the final
    host doesn't need a separate remotePattern.

Path-Level Smoke Test (Group-Level Acceptance — to be executed at the
combined fn-15.1+fn-15.2 PR against the Vercel preview):

  For each unique host in `events.image_url` WHERE event_score IS NOT NULL
  AND start_date >= NOW() AND publish_status = 'published' ORDER BY
  event_score DESC LIMIT 500, pick 3 random URLs and curl them through:

    GET <preview-url>/_next/image?url=<encoded>&w=640&q=75

  Expected: HTTP 200 + content-type image/webp OR image/avif.
  Failure mode: HTTP 400 "url parameter is not allowed" → add the host
  to next.config.ts remotePatterns or narrow an existing wildcard.

  (Postgres credentials are not available inside the agent worktree, so
  this smoke test runs at PR time as part of the manual deploy gate.
  The Group PR will append the per-host result table to this file.)

Decision: NO new patterns added in fn-15.1. The existing wildcards already
cover the entire known Landing-card host set. If the Group-level smoke
test surfaces a missed pattern, that PR will append the specific
remotePattern entry.
